# SS_Lib 3.0 Implementation Plan

Status: implemented on the `v3` branch; kept as the design record. Approved on 2026-11-05, with the open questions decided in section 8. Merged pull requests: #22 (PR 0), #25 (PR 1), #29 (PR 2), #32 (PR 3), #33 (PR 4), #34 (PR 5), #36 (the cleanups of decision 5), #38 (PR 6), #39 (PR 7) and #40 (PR 8, documentation). PR 9, the 3.0.0 release, is still to come. [design.md](design.md#version-30) summarizes what 3.0 changed and why, and [migration-3.0.md](migration-3.0.md) what changes for 2.x programs.

3.0 delivers three items from the 2.1.1 review. Each one needs a breaking change:

- **A9**: an instance handle (`ss_bus_t*`) replaces the single global context.
- **S12**: `ss_data_t` records whether it owns its payload.
- **A8**: a mismatch between the library's configuration and the caller's can no longer corrupt memory, and the check runs without the caller opting in.

Everything else stays as it is: C only, C89 to C2y warning-free, zero dependencies, static mode with no heap, one recursive mutex per lock domain, linear lookup, and the removal/retire scheme.

## 1. Decisions

### A9: instance handle

**Decision.** Add an opaque `ss_bus_t`. Every function that touches library state takes `ss_bus_t* bus` as its first argument and keeps its 2.x name. The library has no global state left, except the table of built-in buses in static mode. The library has no default bus.

- `ss_bus_create(&bus, flags)` allocates the bus with `SS_CALLOC` in dynamic mode. In static mode it takes one of `SS_STATIC_BUSES` built-in buses (default 1, in `.bss`) and never uses the heap.
- `ss_bus_create_in(&bus, pool, size, flags)` places the bus in caller memory, in either mode. A NULL pool returns `SS_ERR_NULL_PARAM`. A pool that is too small returns `SS_ERR_BUFFER_TOO_SMALL`. The silent fallback that `ss_init_static` keeps for 2.1 compatibility goes away.
- `ss_bus_destroy(bus)` replaces `ss_cleanup()`. Called from a slot, it is deferred until the bus's outermost call returns, which is the 2.x `closing`/`call_depth` scheme moved into the bus. Using a bus after it is destroyed is undefined, like using memory after `free()`. In 2.x, a call after `ss_cleanup()` returned `SS_ERR_NULL_PARAM`.
- Thread safety is chosen at creation with the `SS_BUS_THREAD_SAFE` flag. This fixes S4 ("decide at init"). `ss_set_thread_safe` and `ss_is_thread_safe` are removed. Without the flag, the bus creates no mutex.
- The error handler is per bus and receives the bus and a user pointer.
- A batch is bound to a bus when it is created (`ss_batch_create(bus)`). That bus supplies the namespace when entries are added and runs the emission. Batches must be destroyed before their bus is destroyed.
- The slot signature does not change. A slot that needs its bus gets it through `user_data`. Changing the signature would break every slot in every program, for little gain.

**ISR queue.** Each bus has its own queue and sequence counter: `ss_emit_from_isr(bus, name, value)` and `ss_process_isr_queue(bus)`. The claim protocol is unchanged (atomic CAS shim or `SS_ISR_CRITICAL_ENTER/EXIT`). The cost is that the queue can no longer be used before initialization: create the bus before enabling the interrupts that emit, and disable those interrupts before `ss_bus_destroy`. An ISR needs the bus pointer, so the application keeps it in a global that it sets before enabling interrupts.

**Rejected alternatives**

| Alternative | Why rejected |
|---|---|
| Keep the 2.x global API and add `ss_bus_*` variants next to it | Doubles the API, the docs and the code size on small targets. The global stays the easy path, so testing in isolation stays opt-in. |
| A default bus inside the library (`ss_default_bus()`, or a NULL bus meaning the default) | Brings the global back, with its init-order and thread questions (C89 has no `call_once`). With NULL as the default, a failed create would quietly run against the global bus. A program that wants a global writes one line (`static ss_bus_t* bus;`); the migration guide shows a 10-line wrapper. |
| A public `struct ss_bus` that callers can declare | Its layout depends on configuration, which is exactly A8. Every internal change would also become an ABI break. |
| Pass the bus to slots (new slot signature) | Breaks every slot function. `user_data` already covers it. |
| One global ISR queue whose entries name a bus | Keeps "usable before init", but brings back global state. Each drain must skip other buses' entries, and a destroyed bus leaves orphan entries. |
| A separate `ss_isr_queue_t` that the caller attaches to buses | More API for a rare need, and its size depends on configuration. A minor release can add it. |
| Signal handles (`ss_signal_t*` from register, emit without lookup) | Useful, but a separate feature. It is additive, so a 3.x minor release can add it. |
| Signal and slot pools shared between static buses | Couples buses (one bus can starve another) and needs a lock across buses. Per-bus arrays keep buses independent. |

### S12: `ss_data_t` ownership

**Decision.** Add an `owned` field. The library frees a payload only when `owned` is set, and only `ss_data_set_string` / `ss_data_set_custom` (which copy) set it. Every other way of filling an `ss_data_t` borrows:

- direct field writes, which leave `owned` at 0;
- the new `ss_data_set_string_ref` / `ss_data_set_custom_ref`;
- the `ss_emit_*` helpers;
- the views that slots receive, including views of deferred and batch entries.

Misusing a borrowed or stack object therefore leaks at worst. It never frees memory the library does not own.

- `owned` fits in the padding after `type`, so it costs no space.
- `SS_DATA_INIT` (`{ SS_TYPE_VOID, 0, { 0 } }`) and `ss_data_init()` give an empty object. `SS_DATA_INIT` was checked warning-free with gcc 14 and Apple clang, C89 to C23, `-Wall -Wextra -pedantic -Werror`. A shorter `{ SS_TYPE_VOID }` triggers clang's `-Wmissing-field-initializers`.
- `ss_data_clear()` releases an owned payload and resets the object to `SS_TYPE_VOID`. This makes owned payloads usable on stack objects. `ss_data_destroy()` is `ss_data_clear()` plus freeing an object made by `ss_data_create()`.
- The cleanup function becomes `void (*)(const void* data, size_t size)`. It is called once, on the library's copy, before the library frees that copy. The `const` turns a cleanup that calls `free(data)` (the S12 double free) into a compiler diagnostic.
- `ss_data_set_custom` takes `const void* value`, since it only copies it.

**Rejected alternatives**

| Alternative | Why rejected |
|---|---|
| Separate types: an owning `ss_value_t` and a borrowed view `ss_data_t` | Cleaner in theory, but it doubles the data API for a feature few callers use. |
| Remove the copying setters, so `ss_data_t` is always borrowed | Simplest, but callers that set a string and then free their own buffer lose that ability. |
| Let the cleanup function free the copy and skip `SS_FREE` | The copy comes from `SS_MALLOC`. A caller's `free()` may belong to a different allocator. |
| An ownership flag for strings only | Leaves the custom-data double free. |

### A8: automatic configuration check

**Decision.** Fix the cause and keep a cheap automatic check for what remains.

1. **No configuration macro changes a public type layout or enum value.** Custom data moves into the value union (`value.custom.ptr/size/cleanup`), and `SS_TYPE_CUSTOM` is always declared. The other public structs already have fixed layouts; a new check keeps it that way. Feature flags still gate function declarations. A caller and library that disagree on a flag then get a compile or link error, never memory corruption.
2. **The check runs at bus creation without the caller asking for it.** `ss_bus_create` and `ss_bus_create_in` are macros that pass `SS_ABI_TAG` to the `_abi` functions. Those are new functions, so making them macros breaks nothing. The tag combines an ABI revision number with `sizeof(ss_data_t)`, and it fits a 16-bit `size_t` (AVR). It catches what flags no longer can: compiler options such as `-fshort-enums` or packing, and a header from another version. A mismatch returns `SS_ERR_CONFIG_MISMATCH`. FFI callers that cannot use the macros call the `_abi` functions directly.
3. **`make check-abi`** compiles a probe in every configuration from `check_standards.sh` and fails if any public struct size or offset, or any enum value, differs between configurations. It runs in `test-all` and in CI.

**Rejected alternatives**

| Alternative | Why rejected |
|---|---|
| Encode the flags in every symbol name (`#define ss_emit ss_emit_c1t0...`) | Catches every mismatch at link time, but breaks `dlsym`/FFI users and debugger names, and a distro library could only match one configuration. Once layouts no longer depend on flags, there is nothing left for it to protect. |
| One marker symbol referenced from the header | A `static` reference in a header triggers `-Wunused-const-variable` under `-Wall` in C, and C89 has no portable "used" attribute. Referencing it from the create macro gives the same coverage as the runtime tag. |
| Pass the tag on every call | Costs time on the emit hot path. |
| Keep the check opt-in | That is the problem A8 describes. |

### Other breaking changes in 3.0

These follow directly from the new API:

- Removed: `ss_init`, `ss_init_abi`, `ss_init_static`, `ss_init_static_abi`, `ss_get_required_pool_size` (now `ss_bus_pool_size`), `ss_cleanup`, `ss_set_thread_safe`, `ss_is_thread_safe`.
- Removed: the `SS_STATIC_CONTEXT` configuration macro (now `SS_STATIC_BUSES`).

Error code numbers stay as they are. `SS_ERR_BUFFER_TOO_SMALL` (from `ss_bus_create_in`) and `SS_ERR_INVALID_TYPE` (queuing custom data in a library built without custom data) start being returned. Further cleanups are open question 5.

## 2. Public API sketch (changed parts)

```c
/* ---- Bus ---------------------------------------------------------- */
typedef struct ss_bus ss_bus_t;                 /* opaque */

#define SS_BUS_THREAD_SAFE 0x1u                 /* needs SS_ENABLE_THREAD_SAFETY */

#define SS_ABI_REVISION 1                       /* bumped when a public layout changes */
#define SS_ABI_TAG ((size_t)(sizeof(ss_data_t) * 16u + SS_ABI_REVISION))

ss_error_t ss_bus_create_abi(ss_bus_t** bus, unsigned int flags, size_t abi_tag);
ss_error_t ss_bus_create_in_abi(ss_bus_t** bus, void* pool, size_t pool_size,
                                unsigned int flags, size_t abi_tag);
#define ss_bus_create(bus, flags) ss_bus_create_abi((bus), (flags), SS_ABI_TAG)
#define ss_bus_create_in(bus, pool, size, flags) \
    ss_bus_create_in_abi((bus), (pool), (size), (flags), SS_ABI_TAG)
size_t ss_bus_pool_size(void);                  /* bytes for ss_bus_create_in, any alignment */
void ss_bus_destroy(ss_bus_t* bus);             /* NULL is a no-op; deferred inside a slot */
/* Errors: SS_ERR_NULL_PARAM, SS_ERR_MEMORY, SS_ERR_BUFFER_TOO_SMALL,
 * SS_ERR_WOULD_OVERFLOW (static mode: all built-in buses in use),
 * SS_ERR_CONFIG_MISMATCH (tag differs, or a flag the library lacks). */

/* ---- Every stateful function gains the bus; names are unchanged ------ */
ss_error_t ss_signal_register(ss_bus_t* bus, const char* signal_name);
ss_error_t ss_connect_ex(ss_bus_t* bus, const char* signal_name, ss_slot_func_t slot,
                         void* user_data, ss_priority_t priority, ss_connection_t* handle);
ss_error_t ss_disconnect_handle(ss_bus_t* bus, ss_connection_t handle);
ss_error_t ss_emit(ss_bus_t* bus, const char* signal_name, const ss_data_t* data);
ss_error_t ss_emit_int(ss_bus_t* bus, const char* signal_name, int value);
ss_error_t ss_flush_deferred(ss_bus_t* bus);
ss_error_t ss_emit_from_isr(ss_bus_t* bus, const char* signal_name, int value);
ss_error_t ss_process_isr_queue(ss_bus_t* bus);
size_t     ss_get_signal_count(ss_bus_t* bus);
/* ...likewise: register_ex, unregister, exists, connect, disconnect,
 * disconnect_all, emit_void/float/double/string/pointer, emit_namespaced,
 * emit_deferred, set/get_namespace, get_signal_list, memory and perf stats,
 * enable_profiling, set/get_max_slots_per_signal, enable/disable_trace. */

ss_batch_t* ss_batch_create(ss_bus_t* bus);     /* the batch belongs to bus */
ss_error_t  ss_batch_add(ss_batch_t* batch, const char* signal_name, const ss_data_t* data);
ss_error_t  ss_batch_emit(ss_batch_t* batch);
void        ss_batch_destroy(ss_batch_t* batch);

typedef void (*ss_error_handler_t)(ss_bus_t* bus, ss_error_t error, const char* msg,
                                   void* user_data);
void ss_set_error_handler(ss_bus_t* bus, ss_error_handler_t handler, void* user_data);

/* Unchanged: ss_version, ss_error_string, ss_free_signal_list, ss_data_get_*. */

/* ---- Data (no bus) -------------------------------------------------- */
typedef void (*ss_cleanup_func_t)(const void* data, size_t size);  /* must not free data */

typedef enum {
    SS_TYPE_VOID, SS_TYPE_INT, SS_TYPE_FLOAT, SS_TYPE_DOUBLE,
    SS_TYPE_STRING, SS_TYPE_POINTER, SS_TYPE_CUSTOM   /* always declared */
} ss_data_type_t;

typedef struct ss_data {
    ss_data_type_t type;
    unsigned char owned;          /* nonzero: the string/custom payload is the library's copy */
    union {
        int i_val;
        float f_val;
        double d_val;
        const char* s_val;
        void* p_val;
        struct {
            void* ptr;
            size_t size;
            ss_cleanup_func_t cleanup;    /* only when owned */
        } custom;
    } value;
} ss_data_t;                      /* same layout in every configuration */

#define SS_DATA_INIT { SS_TYPE_VOID, 0, { 0 } }
void       ss_data_init(ss_data_t* data);       /* = SS_DATA_INIT, for memory of any content */
void       ss_data_clear(ss_data_t* data);      /* free owned payload, become SS_TYPE_VOID */
ss_error_t ss_data_set_string(ss_data_t* data, const char* value);        /* copies: owned */
ss_error_t ss_data_set_string_ref(ss_data_t* data, const char* value);    /* borrows */
#if SS_ENABLE_CUSTOM_DATA
ss_error_t ss_data_set_custom(ss_data_t* data, const void* value, size_t size,
                              ss_cleanup_func_t cleanup);                  /* copies: owned */
ss_error_t ss_data_set_custom_ref(ss_data_t* data, void* value, size_t size); /* borrows */
#endif
/* ss_data_create/destroy and the scalar setters keep their signatures.
 * Every setter releases the previous payload only if it is owned. */
```

## 3. Static and embedded builds

- **RAM per bus.** One bus costs what the 2.x context costs: signal array, slot array, deferred queue, namespace buffer. On a 64-bit host with the embedded preset (16 signals, 32 slots), `ss_get_required_pool_size()` measures 5263 bytes, or 4239 with `SS_MINIMAL_BUILD`. 32-bit targets need less; PR 5 records the Cortex-M figure from the CI embedded job. A second bus costs the same again, so `SS_STATIC_BUSES` defaults to 1. A 1-bus 3.0 program uses the same RAM as 2.x, except for the change in the next item.
- **`ss_data_t` size.** The fixed layout is 24 bytes on Cortex-M0 (measured with clang `--target=thumbv6m-none-eabi`) and 32 bytes on 64-bit hosts. In 2.x it is 16 bytes without custom data and 32 with it on Cortex-M0, and 16 or 40 on 64-bit hosts. Deferred entries contain one `ss_data_t`, so the minimal embedded preset grows by 8 × `SS_DEFERRED_QUEUE_SIZE` = 128 bytes per bus. Dropping `cleanup` would keep it at 16 bytes (open question 1).
- **ISR queue.** It moves from a global array into the bus: `SS_ISR_QUEUE_SIZE` × (name buffer + 3 ints), about 700 bytes per bus with the defaults on 32-bit. With one bus this is the same RAM as 2.x, now inside the bus storage.
- **`ss_init_static` becomes `ss_bus_create_in`.** It works in both modes. The pool size is a runtime value (`ss_bus_pool_size()`), as in 2.x (open question 2). There is no silent fallback any more.
- **No heap in static mode.** Register, connect, emit, deferred, ISR, namespace, disconnect, unregister and destroy stay heap-free on every bus. `test_memory` checks this with two buses. `ss_data_set_*_ref` adds a heap-free way to fill a data object. `ss_data_set_string`/`_custom`, `ss_get_signal_list` and `ss_batch_create` still allocate, as in 2.x.
- **Built-in bus table (static mode).** Claiming and releasing built-in buses is not locked. Create and destroy them from one thread, normally at startup. Dynamic-mode creation only calls `SS_CALLOC` and is safe from any thread.
- **Code size.** Each call gains a register argument and loses a global load. Every PR that changes `src/` reports `arm-none-eabi-size` for the CI M0/M4 builds, before and after.

## 4. Thread-safety model per bus

- Each bus created with `SS_BUS_THREAD_SAFE` has its own recursive mutex: pthread recursive mutex or `CRITICAL_SECTION`, as in 2.x. Different buses share no mutable state and never contend.
- Inside a bus, nothing changes from 2.x. `bus_enter`/`bus_leave` (today's `ctx_enter`/`ctx_leave`) lock, count depth and defer destruction. Slots run with the lock held. The error handler runs after unlocking.
- **Cross-bus calls from slots.** A slot of bus A that calls bus B holds A's lock while it takes B's lock. Two threads making such calls in opposite directions (A to B and B to A) can deadlock. Rule: cross-bus calls from slots go in one direction only. The docs and the `ss-lib` skills state this rule.
- `ss_bus_destroy` is not thread-safe with respect to other threads using the same bus (same as `ss_cleanup` today).
- Data functions take no lock; each object belongs to its caller. A batch must not be used from two threads at once (unchanged).
- The ISR path takes no lock and is per bus.
- `test_threads` (under `make test-tsan`) covers several threads on one bus, threads on separate buses, and one-direction cross-bus emission.

## 5. Single header, C89 copy, packaging

- **Single header.** It is still generated by `make single-header`, and `check-single-header` stays in `test-all`. The `ss_bus_create` macros and `SS_ABI_TAG` live in the header part. The built-in static buses live in the translation unit that defines `SS_IMPLEMENTATION`. Nothing else changes.
- **C89 copy.** Every PR that edits `src/ss_lib.c` runs `scripts/check_c89_sync.sh --fix`. The plan adds no C99/C11 constructs: the macros are not variadic and no new atomics are needed.
- **Version and soname.** The first PR on the 3.0 branch sets the version to 3.0.0, so no build of the 3.0 branch can be installed as `libss_lib.so.2`. The Makefile and CMake derive `libss_lib.so.3` / `libss_lib.3.dylib` (compatibility version 3.0.0) from the header.
- **pkg-config and CMake.** The names stay `ss_lib.pc`, `lib/cmake/ss_lib` and `include/ss_lib/`. `find_package(ss_lib 3)` matches; a request for 2 is rejected (`SameMajorVersion`, and the hand-written `ss_libConfigVersion.cmake.in` for `make install`). The 2.x and 3.x runtime libraries can be installed side by side. Their development files cannot share one prefix, as with most C libraries. Renaming the package to `ss_lib3` was rejected: it adds names for little gain. `ss_lib.pc` keeps carrying the feature flags, because they still gate declarations.
- **`scripts/check_install.sh`** today hard-codes major 2 (`find_package(ss_lib 2)`, rejects 3). PR 0 makes it derive the expected major from `scripts/version.sh` and assert the installed soname. Its test program moves to the bus API in PR 5.
- **Homebrew.** The formula lives in the tap repository (`dardevelin/ss-lib`), not here. At release: new URL and sha256, and a `test do` block using the bus API. The README's `find_package(ss_lib 2)` becomes 3. Whether to keep a `ss-lib@2` formula is open question 4.

## 6. Migration from 2.x

The new `docs/migration-3.0.md` is written section by section by the PRs that make each change. Outline:

1. **Create and destroy a bus.** `ss_init()` and `ss_init_abi(SS_ABI_TAG)` become `ss_bus_create(&bus, 0)`. `ss_init_static(pool, n)` becomes `ss_bus_create_in(&bus, pool, n, 0)`, which now fails if the pool is too small. `ss_cleanup()` becomes `ss_bus_destroy(bus)`.
2. **Add `bus` as the first argument** to every stateful call (table of functions). Every such call fails to compile until it is changed, because the argument count changes; no call silently changes meaning. The guide gives a `sed` recipe for the common case, and a 10-line wrapper for programs that want one global bus.
3. **Thread safety:** `ss_set_thread_safe(1)` becomes `SS_BUS_THREAD_SAFE` at creation.
4. **Error handler:** new signature with bus and user data.
5. **Batches:** `ss_batch_create(bus)`.
6. **ISR:** pass the bus. Create it before enabling the interrupts that emit.
7. **Data:**
   - `custom_data`/`size`/`custom_cleanup` move to `value.custom` (prefer `ss_data_get_custom`).
   - Cleanup functions take `(const void*, size_t)`. Compile with `-Werror=incompatible-pointer-types` while migrating, because older compilers only warn here.
   - Use `ss_data_clear` for stack objects that use the copying setters.
   - A hand-written `s_val` on an `ss_data_create` object is no longer freed by `ss_data_destroy`. 2.x documented this as misuse.
8. **Configuration:** `SS_STATIC_CONTEXT` becomes `SS_STATIC_BUSES`. Flags no longer change layouts, but must still match, because they gate declarations.
9. **Build:** relink against soname 3, use `find_package(ss_lib 3)`, and download a new single header.

**Compatibility layer: not worth it.** A 2.x-style header would need function-like macros with the same names as the 3.0 functions (`#define ss_emit(n, d) ss_emit(g_bus, n, d)`). The meaning of `ss_emit` would then depend on which header a file includes, which confuses debuggers and the single header. It would not cover the data and error-handler changes, which break source anyway. Because the compiler finds every call that must change, the migration is mechanical.

## 8. Decisions on the open questions (2026-11-05)

1. **`cleanup` stays in `ss_data_t`.** Without it, an application whose custom payloads hold resources has to release every library copy itself. The cost (24-byte `ss_data_t` on Cortex-M, 128 bytes more per bus in the minimal embedded preset) is recorded in the embedded guide.
2. **No compile-time pool size.** `ss_bus_pool_size()` stays a runtime value, as in 2.x. A 3.x minor release can add a compile-time size if a user needs one.
3. **Branching.** 3.0 is developed on the integration branch `v3`, with pre-release tags `v3.0.0-rc.N` there; `main` stays on 2.2.x until 3.0.0 is merged into it. After 3.0.0, 2.2.x receives security fixes on a `release/2.x` branch: PR 9 makes `release.yml` accept final `v2.*` tags from that branch, and `SECURITY.md` lists 2.2.x as supported for security fixes.
4. **Homebrew.** At the 3.0.0 release the tap gets a keg-only `ss-lib@2` formula (2.2.x) next to `ss-lib` (3.x).
5. **Other breaking cleanups in 3.0:** (a) remove the deprecated public `SS_TRACE` macro; (b) remove `SS_ERR_TIMEOUT` and `SS_ERR_ISR_UNSAFE`, keeping the numbers of the other codes; (c) `ss_error_t ss_get_namespace(ss_bus_t* bus, char* buf, size_t size)` copies the namespace into the caller's buffer, which removes the 2.x rule that the returned buffer must not be read while another thread changes it (3.0 changes this function's signature anyway). All three landed in their own pull request (#36) after PR 5, so PR 5 changed only the bus API. (d), a caller-allocated batch for static mode, is additive and waits for a 3.x minor release.
6. **Confirmed:** no default bus in the library and no compatibility header; the migration guide shows a wrapper for programs that want one global bus.
